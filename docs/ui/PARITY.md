## Outfitter action path

`PlanetPanel.cpp` pushes `OutfitterPanel`. `ShopPanel::Draw` owns shared item grid and fleet sidebar. `ShopPanel::KeyDown` handles escape/landed keys, help, map, arrows, page/home/end, group digits, park, Tab, find and then delegates action letters to `OutfitterPanel::HandleShortcuts`. `OutfitterPanel::CanMoveOutfit` validates source and destination; `MoveOutfit` executes. `ShopPanel::CheckForMissions` may offer an OUTFITTER mission. `ShopPanel::ValidateSelectedShips` removes stale ship pointers after mission effects. Selection and category collapse are not cosmetic: `ShopPanel` keeps selected ship set and `PlayerInfo::Collapsed(...)` state.

### Route matrix

Quantity text defaults to 1; `MoveOutfit` parses it with `stoi`. When a ship participates, the loop count is **per selected ship**; for hold/shop-only moves it is a total. Actual transfer can be smaller. `CanMoveOutfit` checks presence, sale/stock, credits including required licenses, attributes/slots, cargo mass, maps/licenses and location restrictions. `ShopPanel::TransactionResult` carries `canSource`, `canPlace` and a message, which control some shortcut fallbacks.

| Source -> destination | Native execution and allocation | Price/stock/side effects |
| --- | --- | --- |
| Shop -> ship (`b`) | Repeated rounds pick eligible ships with the fewest installed, then install one each until quantity, fit, stock or money stops. | Stock depreciation value recalculated after each purchase; credits and local stock updated; crew may increase within bunks; ship recharged. Required license purchased first. Map/license items are permanent special cases. |
| Shop -> cargo (`c` fallback) | Total quantity clipped by finite local stock, fleet cargo mass and affordable total. | Stock depreciation total price, credits and stock change; returns a failure when no affordable cargo item. |
| Shop -> storage (`r` fallback) | Total quantity clipped by finite local stock and affordability; storage has no cargo capacity test here. | Same purchase accounting. |
| Cargo -> ship (`i` first) | Per-ship rounds choose eligible ships with fewest installed; stop when hold is empty. | Removes cargo, installs, adjusts required crew within bunks, recharges. |
| Storage -> ship (`i` fallback) | Same allocation, only when cargo result cannot source. | Removes storage, adjusts ship/crew/recharge. |
| Ship -> shop (`s` fallback) | Per-ship rounds choose ships with most installed; `CanMoveOutfit` checks dependent attributes. | Fleet depreciation sale value; credits and local stock increase; required crew decreases; ship recharged. Linked outfits may also be removed and sold. |
| Ship -> cargo (`u` first) | Per-ship uninstall; if cargo becomes full, destination changes to storage for remaining items in the call. | Crew/recharge changes; linked outfits also removed and routed, with cargo/storage split. `FreePrecise() > mass` in the primary uninstall branch needs exact-fit characterization. |
| Ship -> storage (`u` fallback; `r` second) | Per-ship uninstall directly to storage when chosen/fallback applies. | Crew/recharge; linked outfits to storage. |
| Cargo -> shop (`s` first) | Total quantity removed from hold. | Fleet depreciation value, credits and local stock increase. |
| Storage -> shop (`s` second) | Same; used if cargo sale fails. | Same sale accounting. |
| Cargo -> storage (`r` first) | Total quantity transferred between holds. | No sale or ship modification. |
| Storage -> cargo (`c` first) | Total quantity transferred subject to hold behavior/capacity. | No purchase if this succeeds. |

No ship -> ship route is exposed by this function. A map can only be bought from shop toward ship and updates mapped systems; a license item similarly grants a permanent license. Do not infer normal stock or depreciation behavior for these special cases from the ordinary route rows. `CanMoveOutfit` rejects unavailable shop items unless locally stocked and distinguishes no selection, no ship, insufficient credits, blocked attributes, missing cargo/storage quantity and inadequate cargo space.

### Shortcut and non-transaction parity

- `s`: cargo -> shop, then storage -> shop, then selected ships -> shop.
- `r`: cargo -> storage, then ships -> storage, then shop -> storage.
- `c`: storage -> cargo, then shop -> cargo.
- `i`: cargo -> ships; storage fallback only if cargo cannot source.
- `u`: ships -> cargo; storage fallback only if the first result cannot place.
- `b`: shop -> ships. Buttons and action letters are drawn/handled in `OutfitterPanel`/`ShopPanel` and must remain reachable.
- `ShopPanel::KeyDown`: `l`, `d`, Escape or Ctrl/GUI+W close; Help invokes multiple contextual topics; Map opens map outfitter; arrows/page/home/end move selection/scroll; `f` opens search; Tab changes pane; `k` or Shift+P parks/unparks selected escorts; digits recall groups, Shift+digit toggles group selection, Ctrl/GUI+digit assigns groups.
- `Panel::Modifier` multiplies quantity by 5 for Shift, 20 for Ctrl/GUI and 500 for Alt; `ShopPanel::Draw` writes that value into the quantity dropdown while a modifier is held and restores 1 on release. Test combined modifiers and typed quantity separately.
- `ShopPanel::Click` selects an item without transacting; Shift-click on a category toggles all collapse states. Sidebar Shift-click extends selection across present ships; Ctrl/GUI-click toggles a ship; double-click selects ships that `Imitates` the clicked ship. `ShopPanel::Drag` calls `PlayerInfo::ReorderShip` when dragged over another ship.
- `OutfitterPanel::CheckRefill` follows the ammo-refill preference and may ask via `DialogPanel`; `Refill` visits eligible ships and takes ammo from storage, then cargo, then local shop/stock, changing credits and stock for purchases. The visibility filters cover for-sale, installed, cargo and storage. The exact refill event/save trace remains a later characterization fixture.

## M1-B read-only catalog boundary

`PlanetPanel` opens the opt-in `ReadOnlyOutfitterPanel` with Ctrl+Shift+O at a usable Outfitter; ordinary O still opens `OutfitterPanel`. The M1-B panel reads the same merged sale set but is independent of `ShopPanel` and contains no transaction, mission-offer, refill, save, or player-state write call. Source tabs, category, search, sort, selection, selected ships, and scroll offsets are panel-local. The active panel traps game shortcuts; a focused `Edit` child consumes typed search letters. The focused integration test checks unchanged credits, crew, ship count, one installed outfit, cargo, and storage after keyboard browsing. The inspected disposable save changed only normal playtime during the native session.

The catalog's price column and explicit detail label show `Outfit::Cost()` as **base price**. This is not a quoted purchase price or depreciation/transaction preview. Actual shop availability is `Sale<Outfit>::Has`; player-owned local stock is `PlayerInfo::Stock`. An already-held `* License` outfit follows the legacy visible-license exception and is labeled as held, even if this shop does not sell it. Fleet cargo and current-planet storage are separate. Installed quantities refer to the view's selected ship or all selected ships here, never fleet cargo. Native category precedence is preserved, with visible plugin categories appended by name. Custom attributes use the existing `OutfitInfoDisplay` fallback. M2 must still characterize the legacy action paths and exact transaction prices, allocation, missions, and save/event effects before connecting a modern purchase flow.
